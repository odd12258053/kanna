# ADR-0006: Fuzzing on nightly plus a stable pseudo-fuzz test

Status: Accepted (2026-09-26)

## Context

SPEC.md requires `cargo-fuzz` fuzzing of the lexer. `cargo fuzz` needs a
nightly toolchain, which must not become a requirement for running the
ordinary test suite or for the MSRV check.

## Decision

* The fuzz harness (`hasami-core/tests/common/harness.rs`) is a plain
  function `exercise(args, script)` that drives the parser and asserts
  input-independent invariants: termination within a size-derived bound,
  `Ok(None)` is sticky, every value handed out is a byte-suffix of an input
  argument, long names never contain `=`, and nothing panics.
* `hasami-core/fuzz/` is a standard `cargo fuzz` crate whose single target
  includes that harness by `#[path]` and feeds it `arbitrary`-derived input.
  Run with `cargo +nightly fuzz run lexer` from `hasami-core/`.
* `hasami-core/tests/pseudo_fuzz.rs` runs the same harness on stable Rust
  over 200 000 command lines generated by a seeded xorshift PRNG from an
  alphabet chosen to hit every lexer branch (`-`, `--`, `=`, multi-byte
  UTF-8, ill-formed bytes, WTF-8 surrogates, truncated sequences). It runs
  in about half a second and is part of `cargo test`. The iteration count is
  overridable with `HASAMI_PSEUDO_FUZZ_ITERS`.

## Consequences

* Every `cargo test` run gets fuzz-like coverage with no extra tooling.
* CI runs the libFuzzer target for a fixed time budget on nightly; crashes
  found there are turned into regular regression tests in `tests/lexer.rs`.
* The invariants are deliberately weak enough to hold for any input; the
  precise semantics are pinned by the hand-written tests, not by the fuzzer.
