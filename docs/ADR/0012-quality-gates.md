# ADR-0012: Quality gates and how they are measured

Status: Accepted (2026-09-26)

## Context

SPEC.md §5 defines budgets for binary size and clean build time, plus the
usual lint/test/doc/dependency checks, and asks for a comparison against
clap, argh, bpaf, lexopt and pico-args in the argparse-rosetta-rs style.
Numbers are only meaningful if the method is fixed and reproducible.

## Decision

* **One sample CLI, many implementations.** `benches/src/bin/` holds the
  same five-option, one-positional CLI (ADR-0007) written with `hasami-core`,
  the builder, the `cli!` macro, and each competing library. The competing
  libraries sit behind one Cargo feature *each* (`clap`, `lexopt`, ...), so
  a build-time measurement of one library never compiles another, and the
  workspace's own checks never compile any of them.
* **Size** (`benches/size.sh`): `size` profile, delta against `empty`.
  Budgets enforced with `--check`: `core` ≤ 20 KiB, `decl[help]` ≤ 60 KiB,
  and `decl[full] / clap < 0.5` when `--compare` is given.
* **Build time** (`benches/build-time.sh`): `cargo fetch` first, then for
  each variant `cargo clean` of the profile and a timed `cargo build`, dev
  and release. Budgets enforced with `--check`: `core` ≤ 2 s,
  `decl[full]` ≤ 4 s (dev profile). The numbers depend on the machine; CI
  records them and fails only on the budget, and reports quote the machine.
* **CI** (`.github/workflows/ci.yml`): tests on Linux/macOS/Windows with
  stable and on Linux with the MSRV (1.85), for default, no-default and
  all features; `cargo fmt --check`; clippy with `-D warnings` for all and
  no features; `cargo doc` with `-D warnings`; `cargo deny check`
  (`deny.toml`: no wildcard versions, no duplicate versions, licence
  allow-list, `syn` banned outside `hasami-derive`); a check that the
  default feature set of `hasami` has **zero** third-party dependencies;
  the size and build-time gates; and a 60-second libFuzzer run on nightly.
* Size regressions are investigated with `cargo bloat --profile size`.
  Findings so far are recorded in the step reports so that the next person
  does not repeat experiments that made things worse (cold/no-inline
  attributes on error constructors, `Box<dyn Write>` for output).

## Consequences

* A pull request that pushes `decl[help]` over 60 KiB fails CI; the budget
  is a hard gate, not a target.
* Comparison numbers in the README are generated by these scripts and must
  quote the toolchain and machine.
